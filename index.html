API Docs

The Reseller API lets your own app, website or bot sell through a Get Set Robot store: browse the catalogue, check your wallet and place orders that are delivered automatically, paid from your bot wallet.

Introduction

The API is a single HTTPS endpoint. Every call is a request to the base URL with an action query parameter, and every response is JSON. There are four actions: check your balance, list products, place a purchase, and look up an order.

Typical uses: resell a store's catalogue through your own storefront or bot, automate ordering when your own customers buy from you, and reconcile orders programmatically.

Base URL

All requests go to the store's API base URL, which ends in /reseller/api/:

https://<your-api-host>/reseller/api/
Your live API base URL is shown inside the bot under API. Open @Getsetrobot, tap API, and copy the Base URL shown there — use it exactly as displayed, in place of the placeholder above.

Authentication

Every request must carry your API key in the X-API-Key header:

X-API-Key: ch_live_xxxxxxxxxxxxxxxx

Getting a key: open the bot, tap API, then Generate Own API. The full key is shown exactly once, at generation — copy it then. Keys start with ch_live_.

  • One key per user, per store. The key is tied to your wallet in the store that issued it: purchases debit that wallet and orders belong to that store.
  • A key issued by any Get Set Robot store (the main bot or a store bot created with it) works against the same API host — the key itself decides which store, wallet and catalogue a request uses.
  • Regenerating a key replaces it immediately: the old key stops working at once. You can also revoke your key in the bot at any time.
  • Treat your key like a password. Anyone holding it can spend your wallet balance through the API.

A request with a missing or unrecognized key fails with 401 and error unauthorized.

Check balance

GET ?action=balance

Returns the cash balance (in USDT) of the wallet that owns the key.

curl -H "X-API-Key: YOUR_API_KEY" \
  "https://<your-api-host>/reseller/api/?action=balance"

Response 200:

{
  "ok": true,
  "balance_usdt": 25.5
}

List products

GET ?action=products

Returns the store's full catalogue. The key of each product is the identifier you pass as product_key when purchasing.

curl -H "X-API-Key: YOUR_API_KEY" \
  "https://<your-api-host>/reseller/api/?action=products"

Response 200:

{
  "ok": true,
  "products": [
    {
      "key": "ebook_bundle_pro",
      "name": "Ebook Bundle — Pro",
      "stock": 25,
      "price_usdt": 4.99,
      "price_inr": 499,
      "category": "Ebooks",
      "description": "The complete ebook bundle, delivered instantly."
    }
  ]
}
FieldMeaning
keyProduct identifier. Use it as product_key in a purchase.
nameProduct name.
stockUnits currently available.
price_usdtPrice per unit in USDT. Purchases are settled in USDT.
price_inrPrice per unit in INR, for display.
categoryCatalogue category.
descriptionProduct description (may be empty).

Purchase

POST ?action=purchase

Places an order and delivers it. The total (price_usdt times quantity, minus any coupon discount) is debited from the wallet of the key's owner, in the store that issued the key.

HeaderRequiredNotes
X-API-KeyYesYour API key.
Idempotency-KeyYesA unique string you choose for this purchase. See Idempotency below.
Content-TypeYesapplication/json
Body fieldTypeNotes
product_keystring, requiredThe product's key from the products list. product_id is accepted as an alias.
quantityinteger, optionalDefault 1. Minimum 1, maximum 500.
couponstring, optionalA coupon code for the store. An invalid coupon fails the whole purchase with 422 coupon_invalid — it is never silently ignored, and no order or coupon use is consumed.
 
curl -X POST \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Idempotency-Key: order-1001" \
  -H "Content-Type: application/json" \
  -d '{"product_key": "ebook_bundle_pro", "quantity": 2}' \
  "https://<your-api-host>/reseller/api/?action=purchase"

Response 201:

{
  "ok": true,
  "order_id": "RA-20261122-9F3AC41D07B2E6AA",
  "delivered": [
    "ITEM-CODE-0001",
    "ITEM-CODE-0002"
  ]
}
  • Order IDs from the API start with RA-. Keep the order_id — it is how you look the order up later.
  • Stock products: the delivered items are returned in delivered, one per unit. If fewer units remain than requested, the purchase fails with 422 out_of_stock and nothing is debited.
  • Service products: the order's status is Service Ticket Created and delivered contains a message with the ticket reference (TCK-...). The store team then delivers through the bot.
  • ZIP / source-code products: the file is sent to the buyer in the bot chat, and the response includes "file_sent": true (or false if the bot could not message the buyer — the file stays recorded on the order).
  • Products fulfilled by an upstream store: your wallet is debited only after the upstream store confirms delivery. If upstream fulfilment fails, you get 502 upstream_fulfilment_failed and no debit.
  • If a coupon was applied, the response also includes coupon, discount_usdt and the final total_usdt.
  • If the wallet cannot cover the total, the purchase fails with 402 insufficient_balance and no order is created.

Get an order

GET ?action=order&order_id=RA-...

Returns the full stored record of one of your orders. You can only read orders that belong to your key — an unknown ID, or an order belonging to a different key, returns 404 not_found.

curl -H "X-API-Key: YOUR_API_KEY" \
  "https://<your-api-host>/reseller/api/?action=order&order_id=RA-20261122-9F3AC41D07B2E6AA"

Response 200:

{
  "ok": true,
  "order": {
    "id": "RA-20261122-9F3AC41D07B2E6AA",
    "userId": 123456789,
    "productId": "ebook_bundle_pro",
    "qty": 2,
    "totalInr": 998,
    "totalUsdt": 9.98,
    "status": "Delivered",
    "delivered": [
      "ITEM-CODE-0001",
      "ITEM-CODE-0002"
    ],
    "at": "2026-11-22T10:15:30.000Z",
    "viaApi": true,
    "idempotencyKey": "order-1001"
  }
}

status is Delivered for completed orders and Service Ticket Created for service products awaiting the store team (service orders then move to In Progress and finally Delivered as the store team works on them). An order interrupted mid-purchase can also appear as Processing, or Failed if that attempt did not complete. Depending on the product, the record can also carry upstreamOrderId (upstream-fulfilled products), zipFileSent (ZIP products) and couponCode / discountUsdt (coupon orders).

Idempotency

Every purchase must send an Idempotency-Key header — a unique string you choose for that purchase, such as your own order ID. This makes retries safe:

  • If a purchase with the same Idempotency-Key already completed for your key, the API does not create a second order and does not debit again. It responds 409 idempotency_conflict with the original order_id, which you can fetch with action=order.
  • If the earlier attempt with that key was interrupted or failed before completing, a retry with the same key, product and quantity safely resumes and completes that same order instead of creating a new one — you are still charged only once. Retrying with the same key but a different product or quantity returns 409 idempotency_conflict.
  • A purchase sent without the header fails with 400 idempotency_key_required.
  • Rule of thumb: if a purchase request times out, retry with the same Idempotency-Key — never with a new one.

Rate limits

Each API key may make up to 60 requests per minute. Requests beyond that fail with 429 and error rate_limited until the minute window resets. Spread bulk work out instead of bursting it.

Errors

Every error response is JSON with ok set to false and a machine-readable error code. Some errors include extra fields, noted below.

{
  "ok": false,
  "error": "insufficient_balance"
}
HTTPErrorMeaning
400idempotency_key_requiredPurchase sent without an Idempotency-Key header.
400unknown_actionMissing or unknown action. Also returned when a purchase is sent with a method other than POST.
401unauthorizedMissing or invalid API key.
402insufficient_balanceThe key owner's wallet cannot cover the purchase total. No order is created.
403plan_requiredThe key belongs to a store whose current plan does not include Reseller API access. The response includes a message explaining how the store owner can upgrade.
404product_not_foundNo product with that product_key exists in the store.
404not_foundOrder lookup failed: no order with that ID belongs to your key.
409idempotency_conflictThis Idempotency-Key was already used. The response includes the original order_id. No second debit was made.
422quantity_invalidquantity must be an integer between 1 and 500.
422out_of_stockNot enough stock for the requested quantity. Nothing is debited.
422coupon_invalidThe coupon was rejected. The response includes a reason code and a human-readable message. No order is created and the coupon is not consumed.
429rate_limitedMore than 60 requests in a minute for this key. Wait for the window to reset.
502upstream_fulfilment_failedThe product is fulfilled by an upstream store and that fulfilment failed. The response includes a reason. Your wallet was not debited.
500internal_errorUnexpected server error. For purchases, retry with the same Idempotency-Key.
